# token-counter

[![Тесты](https://github.com/maarshir/token-counter/actions/workflows/tests.yml/badge.svg?branch=main)](https://github.com/maarshir/token-counter/actions/workflows/tests.yml)

Считает, сколько стоит запрос к языковой модели: по числу токенов из ответа API или по тексту промпта, ещё до отправки.

Одной фразой для резюме: библиотека и командная строка для подсчёта стоимости запросов к моделям с точной денежной арифметикой и таблицей цен, у каждой цены есть дата и источник.

## Зачем

Когда гоняешь промпты на наборе задач, как в моём [promptdiff](https://github.com/maarshir/promptdiff-), быстро возникает вопрос: сколько это стоит и какой вариант промпта дешевле при том же качестве. API возвращает число токенов, но не деньги, а цены разные у каждой модели и отдельные для входа, выхода и кэша промпта. token-counter переводит токены в доллары и помогает прикинуть траты заранее.

## Как это выглядит

```text
$ python -m token_counter cost --model claude-sonnet-4-6 --input 1200 --output 300 --times 1000
Модель: claude-sonnet-4-6 (цены на 2026-09-27)
  вход              $0.0036
  выход             $0.0045
  итого             $0.0081
  за 1000 запросов  $8.10
```

```text
$ python -m token_counter estimate --model claude-sonnet-4-6 --output 512 --times 14 \
    --text "Разбери фразу в строку с полями water, gym, sleep. Выпил 300 мл воды и час был в зале."
Входных токенов: ≈29 (грубая оценка без токенизатора, с запасом)
Модель: claude-sonnet-4-6 (цены на 2026-09-27), ответ до 512 токенов
  вход              $0.000087
  выход             $0.00768
  итого             $0.007767
  за 14 запросов    $0.108738
```

Это настоящий вывод программы. Второй пример показывает верхнюю границу: ответ посчитан как полные 512 токенов, а вход прикинут без токенизатора (см. ниже, почему).

## Что умеет

- Стоимость по известному числу токенов: вход, выход, запись в кэш промпта и чтение из него считаются по своим ценам.
- Прикидка числа токенов по тексту без сети и без ключа. Честно помечена как оценка.
- Точный подсчёт входных токенов для моделей Anthropic через их бесплатный эндпоинт count_tokens (нужен ключ).
- Таблица цен в `token_counter/prices.json`: у каждой модели дата сверки и ссылка на страницу с ценами. Можно подложить свою таблицу через `--prices` или переменную `TOKEN_COUNTER_PRICES`.
- Имя модели с датой в конце (`claude-haiku-4-5-20251001`) находит ту же цену, что и без даты. При опечатке подсказывает похожее имя.
- Разбор usage и из ответа Anthropic (`Usage.from_api`), и из ответа в формате OpenAI, как отвечают Groq и другие совместимые API (`Usage.from_openai`).
- 58 тестов, на Гитхабе идут на Python 3.10 и 3.12 при каждом изменении.

Сейчас в таблице четыре модели Anthropic и две открытые модели на Groq. Цены сверены 27.09.2026 с [ценами Anthropic](https://platform.claude.com/docs/en/about-claude/pricing) и страницами моделей Groq ([gpt-oss-120b](https://console.groq.com/docs/model/openai/gpt-oss-120b), [gpt-oss-20b](https://console.groq.com/docs/model/openai/gpt-oss-20b)), у моделей Groq есть и цена входа из кэша промпта. Цены меняются: перед важным расчётом стоит сверить.

## Как запустить

Нужен Python 3.10 или новее.

```bash
git clone https://github.com/maarshir/token-counter.git
cd token-counter
python -m venv .venv
source .venv/bin/activate      # на Windows: .venv\Scripts\activate
pip install -r requirements.txt
pytest
python -m token_counter models
```

Команды:

```bash
# таблица цен с датами и источниками
python -m token_counter models

# стоимость по токенам из ответа API
python -m token_counter cost --model claude-haiku-4-5 --input 5000 --output 800 --cache-read 20000

# прикинуть по тексту промпта (из файла, из --text или со стандартного ввода)
python -m token_counter estimate --model claude-sonnet-4-6 --file prompt.txt --output 512 --times 100

# то же, но точное число входных токенов через API Anthropic
cp .env.example .env           # вписать ANTHROPIC_API_KEY
export ANTHROPIC_API_KEY=...   # .env сам не читается, переменную нужно выставить
python -m token_counter estimate --model claude-sonnet-4-6 --file prompt.txt --exact
```

Как пакет, без клонирования (появится команда `token-counter`, таблица цен ставится вместе с пакетом):

```bash
pip install "token-counter @ git+https://github.com/maarshir/token-counter"
token-counter models
```

Так он и подключён в promptdiff: в requirements.txt promptdiff стоит эта строка с номером коммита, чтобы обновление цен здесь не меняло отчёты там без ведома.

Из кода:

```python
from token_counter import Usage, cost, find_price, format_usd, load_prices

price = find_price("claude-sonnet-4-6", load_prices())
usage = Usage.from_api(response_json["usage"])   # поле usage из ответа Anthropic API
# для Groq и других OpenAI-совместимых API: Usage.from_openai(response_json["usage"])
print(format_usd(cost(usage, price).total))
```

## Технологии и почему

- **Python и стандартная библиотека.** Для денег `decimal.Decimal`, для командной строки `argparse`. Единственная зависимость `httpx`, и нужна она только для точного подсчёта через API; тот же клиент стоит в promptdiff.
- **JSON для таблицы цен**, а не код. Цены меняются чаще, чем логика, и обновить их должно быть можно без правки пакета.
- **pytest**, сеть в тестах подменена через `httpx.MockTransport`, ключ не нужен.

## Что было непросто

**Деньги нельзя считать во float.** Цена открытой модели на Groq 0.075 доллара за миллион токенов, запрос стоит доли цента, и таких запросов тысячи. Во float 0.1 хранится не точно, и ошибка накапливается при сложении. Поэтому цены лежат в JSON строками, читаются в `Decimal`, а число с точкой без кавычек загрузчик отклоняет: оно уже прошло через float при чтении JSON. Округление только при выводе. Тест проверяет, что 10 000 одинаковых запросов дают ровно 0.0105; то же сложение во float даёт 0.010500000000000956.

**Мелкие суммы не должны превращаться в $0.00.** Обычное округление до центов показало бы, что прогон на 14 запросов бесплатный. Вывод от доллара и выше идёт с двумя знаками, ниже доллара до шести знаков без лишних нулей.

**Честно про точность подсчёта токенов.** Точное число знает только токенизатор модели. У Anthropic он не опубликован, у OpenAI словари токенизатора скачиваются из сети при первом запуске, а мне нужна была работа без сети. Поэтому `estimate` делает прикидку по классам символов: латиница примерно 4 символа на токен (так пишет OpenAI про английский), кириллица мельче, знаки и эмодзи по токену на символ. Коэффициенты подобраны грубо и не откалиброваны на настоящем токенизаторе, поэтому выбраны с запасом в большую сторону и в выводе стоит «≈». Для точного числа есть `--exact` через count_tokens API или поле usage в ответе модели.

**Кэш промпта стоит по-другому.** У Anthropic `input_tokens` в ответе не включает токены, записанные в кэш промпта и прочитанные из него: они приходят отдельными полями, запись дороже обычного входа, чтение в разы дешевле. `Usage.from_api` раскладывает поля как есть. Если в таблице у модели нет цены кэша, а такие токены есть, считать по цене обычного входа было бы враньём, поэтому программа останавливается с ошибкой.

**В формате OpenAI кэш посчитан наоборот.** У Groq и OpenAI `prompt_tokens` уже включает токены, прочитанные из кэша, а их число лежит отдельно в `prompt_tokens_details.cached_tokens`. Если разложить это так же, как у Anthropic, кэш посчитался бы дважды: и по цене входа, и по цене кэша. Поэтому для этого формата отдельный `Usage.from_openai`, который вычитает кэш из входа, и тест на пример из документации Groq (4608 токенов из кэша). Токены рассуждений у моделей вроде gpt-oss входят в `completion_tokens` и оплачиваются как выход, отдельно их считать не нужно.
